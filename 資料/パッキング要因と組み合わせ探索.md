# パッキング文字数を変える要因と組み合わせ探索

## 結果

以前の20文字版から、描画解像度28.16px・表示最大辺33pxを維持したまま、31文字版を作りました。

`SVG文字パッキング31文字_16x8.sb3`を公式Scratchで読み込むと、緑の旗で1秒ごとに1文字ずつ切り替え、31文字表示後に先頭へ戻ります。1～9・a～vキーでも1文字ずつ選べます。自動再生中のキー表示は次の定時切り替えで上書きされます。

31字形を1枚のSVGに収めています。サイズ・移動制限を回避する空コスチュームも1枚使います。20文字版・15文字版は残しています。

## 容量を変える要因

| 要因 | 影響と確認したこと |
| --- | --- |
| 元コスチュームの幅・高さ | 幅は線分の長さ、高さは文字を置ける範囲を制限します。高さ不足では中央の角度に配置できません。余分な高さを減らすとテクスチャ面積を減らせます。 |
| SVGから作るテクスチャの倍率 | 最大辺2048px、2の累乗倍率という段差があります。16を少し超えて16.01にすると最大倍率128から64に下がり、同じ描画解像度を確保するには字形のSVG座標上の大きさを2倍にする必要があります。単純な寸法増大で逆に容量が落ちる例です。 |
| 1画像の描画解像度 | 同じテクスチャ上で字形が大きいほど配置数は減ります。解像度を下げると数を増やせますが、細部の画質が下がります。 |
| 表示サイズ | 表示サイズが変わるとSVG内の余白と画面上の余白の換算が変わります。描画解像度・表示サイズを混同せず固定して比較しました。 |
| マスク境界からの余白 | 小さくすれば容量は増えますが、丸めや補間による欠け・混入の余裕が減ります。主要結果は2pxを維持しています。 |
| 境界計算が読む整数座標 | 字形の不透明部分がサンプル点に重なると、線分状の凸包が崩れます。今回の探索では字形の外接矩形と2テクセル分の余白で点を避けます。 |
| 各字形の角度・半径・横縦の位置 | 共通半径→可変半径で15→20文字になりました。さらに円弧上という制約を外し、切り出し矩形の角に横・縦それぞれで寄せると30文字前後に増えました。 |
| 角度探索の刻み | 0.5°刻みでは見落とす組み合わせがあります。0.1°まで細かくして16×8で31文字の配置が見つかりました。刻みをさらに小さくしても必ず数が増えるわけではありません。 |
| 凸包の線分の長さ・向き・位置 | 線分を斜めにする候補も調べました。線分が長くなっても、字形を置く領域が画像端で切られる場合があり、対角線が常に有利とは限りません。今回の実装は水平線分です。 |
| 字形・画像の縦横比と輪郭 | 正方形画像より細長い画像のほうが多く配置できる計算例があります。実際の輪郭や字形ごとの異なる外接矩形を使えば改善する可能性があります。今回の31文字版は正方形の枠を使った保守的な計算で、文字を変形していません。 |
| 探索で採用する候補の数 | 今回は各角度に対してサンプル点を避けられる外側の候補を1つ採用しています。複数の候補を同時に比較すればさらに増やせる可能性があります。今回の結果は絶対最大容量の証明ではありません。 |

## 主な比較

### 描画解像度28.16px・表示33px・最低余白2px

| 元寸法 | 配置方法 | 探索の角度刻み | 見つかった数 |
| --- | --- | --- | ---: |
| 32×16 | 共通半径の円弧 | 0.5° | 15 |
| 32×16 | 個別半径の円弧 | 0.5° | 20 |
| 32×16 | 各マスクの角に沿う個別位置 | 0.5° | 29 |
| 32×16 | 各マスクの角に沿う個別位置 | 0.1° | 30 |
| **16×8** | **各マスクの角に沿う個別位置** | **0.1°** | **31** |

16×8で31文字が32×16の30文字より多いのは、整数サンプル点との位置関係と角度候補の組み合わせによる探索結果です。小さい寸法なら常に有利という一般則ではありません。

### 画質を変える場合の計算例

元寸法32×16、表示33px、最低余白2px、角度0.1°で比較。

| 1字形の描画解像度（最大辺） | 見つかった数 |
| --- | ---: |
| 24px | 38 |
| 28.16px | 30 |
| 32px | 27 |
| 40px | 21 |

24px・38文字は数値探索だけで、sb3生成・描画検証はしていません。主要成果は画質を落とさない31文字版です。

### 余白を変える場合の計算例

元寸法32×16、描画解像度28.16px、表示33px、角度0.1°。

| 画面上の最低余白 | 見つかった数 |
| --- | ---: |
| 1px | 34 |
| 2px | 30 |
| 3px | 30 |
| 5px | 27 |

1pxの結果は描画時の欠けや混入に弱くなる可能性があるため、31文字版では2pxを維持しました。

### 画像の縦横比を変える場合の計算例

元寸法32×16、最大辺の描画解像度28.16px、表示最大辺33px、最低余白2px、角度0.25°。

| 埋め込む画像の幅:高さ | 見つかった数 |
| --- | ---: |
| 1:1 | 30 |
| 3:4 または4:3 | 33 |
| 1:2 または2:1 | 39 |

これは細長い画像を想定した幾何計算です。日本語文字を引き伸ばすことを提案するものではありません。実際の輪郭を用いた配置や、不均一な縦横比が混在する配置は未探索です。

## 新しい配置方法

従来は字形の中心を線分中心から半径r、角度2aの円弧上に置いていました。その方法では、切り出し矩形の片方の辺に寄せると他方に余白が残り、空間を十分に使えませんでした。

新方式では、選択角度aにおけるスタンプ範囲の半幅hx=L cos(a)/2、半高さhy=L sin(a)/2を使います。正立した字形の半幅・半高さに余白を足したpx,pyに対して、中心を(x,y)=(hx-px,-hy+py)という角付近に置きます。これを回転前のSVG座標へ逆変換します。サンプル点と重なる場合は横・縦を1テクセルずつ内側にずらします。

全候補の組み合わせについて、他字形の外接矩形が選択範囲から最低2px離れることを相互に確認します。その適合関係のグラフから最大クリークを探索します。候補集合の中での最大集合であり、すべての連続配置に対する最大数ではありません。

## 31文字版の数値

- 元寸法16×8。
- 境界計算用マーカーは(0,0)と(15,0)。凸包は[[0,0],[15,0]]、長さ15の線分。
- 字形のSVG座標上の最大辺0.22。
- 最大テクスチャ倍率128、実際のテクスチャ2048×1024。
- 字形の描画解像度0.22×128=28.16px。
- 表示倍率150（15000%）、表示最大辺0.22×150=33px。
- 31個の異なる日本語字形を収録。

## 実行確認

公式scratch-render・scratch-vmの配布ライブラリをヘッドレスChromeで使い、生成したsb3そのものを実行しました。

1. 1～9・a～vキーで全31文字を個別表示。
2. 各文字で凸包が[[0,0],[15,0]]となり、切り出しスクリプトが完了することを確認。
3. 実際のシルエット2048×1024、最大倍率128を確認。
4. スタンプ画像の全非白画素が選択文字の範囲に収まることを確認。
5. 他字形・校正マーカーを含めず、同じ字形だけを通常表示した参照画像を別途生成。
6. 全31文字のスタンプ画像を参照画像と画素単位で比較し、欠け・余分な画素がないことを確認。比較では各色チャンネル2以下の差を許容しましたが、許容値を超える差分画素数は全字形で0です。
7. 1秒ごとの31文字の順序と、最後から先頭への復帰を確認。
8. 一覧画像`16x8_31文字確認.png`を目視確認。

公式ScratchサイトのエディターUIでは未確認です。読み込み速度と実行速度の比較測定はしていません。

## 再現用ファイル

- `search_packing_combinations.py`: 寸法・線分・配置方式の23条件、上位候補の細かい探索3条件。
- `sweep_packing_factors.py`: 解像度・余白・寸法境界・探索刻みの23条件。
- `refine_packing_search.py`: 最終候補・画像縦横比の11条件。
- 計60条件を比較。各条件の内部では多数の角度・位置候補を探索しています。
- `build_dense_experiment.py --optimized`: 最終31文字版を生成。
- `verify-optimized.cjs`: sb3の単字表示と自動切り替えを実行確認。
- `verify-unmasked.cjs`: マスクなしの参照画像を生成。
- `inspect_optimized.py`: 全画素比較と単字一覧を生成。

結果は`combination-results.json`、`combination-fine-results.json`、`factor-sweep-results.json`、`refined-combination-results.json`、`optimized-verification.json`、`optimized-pixel-check.json`に保存しています。
