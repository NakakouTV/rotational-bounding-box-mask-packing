# 寸法変更による容量の検討

前回の4文字という結果は2×1 SVGと円弧配置に限定した結果です。Bounding box bug全般の容量上限ではありません。

同じ文字解像度（最大テクスチャ上56.32px）、表示33px、余白2pxの正方形外接矩形モデルで、半径と角度を探索しました。

- 4×1 SVG（1×4の回転相当）では円弧配置で2文字。細長い画像に字形全体が収まる条件が厳しいためです。配置方式一般の上限ではありません。
- 4×4 SVGでは6文字。8×8では7文字の配置が見つかりました。
- 16×16も7文字、32×32は探索した条件で6文字でした。サンプル点回避条件と探索刻みの影響があるため、大きい画像ほど容量が減るという一般則を意味しません。

4×4 SVGでは(0,0),(1,0),(2,0),(3,0)に小さな不透明マーカーを置きます。字形はそれ以外の整数座標のサンプル点を避けます。これにより凸包が[[0,0],[3,0]]という長さ3の線分になります。文字を置ける画像の高さが増えたため、長い線分の外接矩形の角付近に字形を置けます。

`packed-font-4x4.svg`には日本語を2組、合計6か所に配置しています。公式scratch-renderの配布ライブラリを使って6か所のスタンプを描画し、`4x4容量実験.png`を生成しました。各選択で凸包が[[0,0],[3,0]]になることも確認済みです。今回の追加検証は描画ライブラリ単独であり、4×4版sb3のVM実行検証はしていません。

字形の角度は23°・34.5°・42°・48°・55.5°・68°、線分中心からの配置半径は1.335です。表示倍率300、文字のSVG内最大辺0.11、最大テクスチャ倍率512なので、表示最大辺33px、最大テクスチャ上最大辺56.32pxです。

さらに検討できる方法:

1. 字形ごとに異なる半径を使う。今回は全字形が同じ半径という制約があります。
2. 正方形外接矩形ではなく実際の輪郭で配置判定する。空白の多い字形では配置を詰められる可能性があります。
3. 整数以外のSVG寸法を使う。境界計算の走査点数とテクスチャ倍率には段差があるため、画像端の余白を最適化できる可能性があります。今回の一部比較では単純な改善は見つかっていません。
4. 凸包を線分以外の少数点にして選択領域を変える。これは新しいマスク構成の探索が必要です。

計算は`compare_dimensions.py`、結果は`dimension-results.json`と`square-dimension-results.json`。数値はいずれも指定した探索モデルでの結果で、任意配置の絶対最大値ではありません。

## 100×100の場合

同じ文字解像度56.32px・表示33px・余白2pxで計算すると、サンプル点を無視した円弧配置では6文字の配置が見つかりました。しかし正方形字形の外接枠が整数サンプル点を一切含まない条件では0文字でした。これは100×100で実現不可能という証明ではなく、現在の保守的な配置モデルが成立しないという結果です。

最大MIP倍率は16、テクスチャは1600×1600です。次の倍率32では3200×3200となり最大辺2048pxを超えるためです。56.32pxの字形はSVG内で最大辺3.52となり、整数間隔のサンプル点を外接枠ごと避けることができません。実際の輪郭なら空白部分にサンプル点を置ける可能性はありますが、追加探索と描画検証が必要です。

整数サンプル点で字形の不透明部分が見つかると、上端マーカーだけの線分状凸包が維持できなくなります。通常の不透明な100×100の矩形なら境界は99×99で、線分にはなりません。100×100への単純な寸法変更だけでは、大量の文字を独立選択できるようにはなりません。
