# リスト参照式の描画

31文字版の各文字の処理を1つのカスタムブロックにまとめ、文字ごとのデータをScratchのリストへ移しました。

## 共通ブロック

`画像を描画 (画像ID) x (x) y (y)`

例: `画像を描画 (語) x (100) y (-50)`。

画像IDを検索して、同じ行番号にある描画パラメーターを読み、指定位置にスタンプします。x・yは画像の中心位置です。画像IDは文字以外の名前にも対応します。ペンは消さないので、文章や複数画像を並べる際にも使えます。未登録の画像IDなら何も描画しません。

「画面を再描画せずに実行する」が有効な共通ブロックです。空コスチュームでの移動制限回避、コスチューム変更、境界計算、スタンプ、非表示までをまとめています。スタンプの直前に、中身が空の `もし〈端に触れた〉なら` を実行します。条件を評価するだけで境界計算が発生するため、「aと言う」は不要です。

## データのリスト

| リスト | 値 |
| --- | --- |
| 画像ID | 日、本、語…など選択に使う名前 |
| 描画X補正 | 指定xから引く位置補正 |
| 描画Y補正 | 指定yから引く位置補正 |
| 描画方向 | スプライトの方向 |
| 描画サイズ | スプライトのサイズ（%） |
| 描画コスチューム | パッキングしたSVGのコスチューム名 |

6本のリストの同じ番号が1つの画像のデータです。全リストの長さと行順を揃えてください。画像IDは重複させないでください。文字と座標を別々のスクリプトに書く必要はありません。

Scratchのデータタブで各リストを表示・確認できます。ステージにリストを表示する必要はありません。データはsb3自体に含まれるため、JSONなどの外部ファイルは実行時に不要です。

## デモ

緑の旗のスクリプトも`画像ID`のリストを参照します。リストの長さだけ繰り返すため、文字数を変えても自動切り替え用の描画スクリプトを増やす必要はありません。

1秒ごとに1文字だけ描画し、最後の文字の次は先頭へ戻ります。デモにはキー操作や入力機能を入れていません。

今後のsb3生成も`生成/scratch_list_renderer.py`の共通コードを使います。以前の個別スクリプト方式の31文字版は`過去の成果物/SVG文字パッキング31文字_16x8_個別スクリプト版.sb3`に保存しています。

## 検証結果

生成したsb3をScratch VMで実行し、31文字すべての描画と1秒ごとの順序・繰り返しを確認しました。マスクなしの参照画像との比較でも、欠けや余分な画素はありませんでした。

加えて、実行中に6本のリストの行を入れ替えても同じ画像IDから同じ文字が表示されること、位置補正値の変更が描画位置に反映されることを確認しました。未登録ID、任意の名前のID、共通ブロックのx・y引数も検証済みです。これらの検証用呼び出しは実行中のVMにだけ追加しており、出力sb3には含めていません。
